# Requirements traceability

This checklist maps every requirement of the build specification
(`specs/INTI.md`: the open-source preamble and sections 1 to 33, with every
section 31 bullet split into its parts) to the files that implement it and the
tests that exercise it. It was compiled on 2026-09-24 from the code and from
`npx vitest list`, and updated after the audit fixes of 2026-09-24, after the
second round of fixes of 2026-09-25, after the third round, and again after
the fourth round of fixes later on 2026-09-25, against the code as it landed; every test file named here exists, and quoted test names are
fragments of real test titles. `tests/unit/docs/status-docs.test.ts` checks
the cited files, the statuses, the stated test numbers (row 32.2), and that
no row denies a command the CLI registers.

Status legend:

| Status | Meaning |
| --- | --- |
| **Tested** | Implemented; offline automated tests exercise it. |
| **Tested offline, live unverified** | Implemented against the provider's documented contract; tested only with fakes or synthetic fixtures; never run against the live service (see [FEATURE_STATUS.md](FEATURE_STATUS.md)). |
| **Documented** | Satisfied by documentation or repository files; checked by review or by the named static check. |
| **Process** | An owner or maintainer rule that code cannot fully enforce. |
| **Partial** / **Gap** | Partly implemented / not implemented. The gap is stated. |

Test paths are relative to `tests/`. "e2e/honest-status" means
`tests/e2e/honest-status.test.ts`, and so on.
