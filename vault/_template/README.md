# {{business_name}}: seo-agent vault

This folder is an Obsidian-compatible vault, but it is plain Markdown. You can
read and edit it with any text editor. Obsidian and community plugins are
optional.

## Who owns what

| Where | Owner | What it holds | How it changes |
| --- | --- | --- | --- |
| `01 Business/` | You (human) | Business facts: offer, customers, differentiators, product facts, claims, brand voice, standing decisions, customer questions | You edit it. seo-agent only reads it through `vault import-business` (validated, versioned). It never writes there. |
| Your own notes and the text outside generated markers | You (human) | Anything you write | Preserved verbatim on every render |
| Properties you add to a generated note (and your tags, aliases, cssclasses) | You (human) | Your own metadata | Kept on every render, with your YAML comments and key order |
| Text between the generated markers | seo-agent | A presentation of database records | Regenerated by `vault render` |
| SQLite database (in the workspace `data/` folder) | seo-agent | Measurements, job state, budgets, approvals, provenance, audit log | The source of truth. Notes present it; editing a note never changes it. |
| Qdrant (in the workspace `qdrant/` folder) | seo-agent | A search index over selected notes and sources | Rebuildable at any time. Never authoritative. |

## Generated notes

Generated notes contain one region between these two HTML comments:

```
<!-- seo-agent:generated:start -->
... regenerated from the database ...
<!-- seo-agent:generated:end -->
```

- Write your own notes above or below the region (for example under
  `## Notes`). That text is always preserved.
- Properties (frontmatter) you add yourself are preserved, including YAML
  comments and their order. Properties seo-agent writes (`id`, `type`, `site`,
  `generated_at`, `source_ids`, ...) are updated in place.
- `tags`, `aliases`, and `cssclasses` are shared: seo-agent adds its own entries
  (for example `seo-agent/page`) and keeps every entry you add. Adding a tag is
  not an edit of generated content.
- If you edit text inside the region or a generated property, seo-agent does
  not overwrite the note. It writes a conflict file next to it,
  `<note>.conflict-<timestamp>.md`, with the proposed new version. Resolve it
  with `npm run cli -- vault resolve "<note path>" --use-generated` (or
  `--detach` to keep maintaining the note by hand), then delete the conflict
  file.
- Every note has a stable `id` property. File names are readable and stay the
  same when titles change.
- Links always use the full vault path, for example
  `[[02 Website/Pages/Pricing|Pricing]]`, so they never become ambiguous.

## Third-party text and plugins that run code

Generated notes include third-party text (scraped pages, forum posts, model
drafts). seo-agent escapes it, so it shows as plain text and can never become a
link, an embed, a Dataview field or query, a code block, or a Templater
command. Plugin features that run JavaScript (Dataview JavaScript queries,
Templater's "trigger on new file creation") are off by default; if you turn
them on, remember that the vault contains text written by others.

## Approvals and trust

Writing `approved: true`, `trusted: true`, or similar properties in any note
authorizes nothing. Production changes (publishing, redirects, canonical,
robots, or analytics changes) require an approval recorded through
`npm run cli -- approvals approve <id>`, bound to the exact proposal.
Scraped text and agent-generated notes can never mark themselves as trusted.

## Folders

- `00 Dashboard/`: static dashboard and an index of generated notes
- `01 Business/`: human-maintained business notes (see the templates inside)
- `02 Website/Pages/`: one note per page (metrics with freshness, route, issues, links)
- `03 Keywords/`, `04 Competitors/`: research presentation
- `05 Content/Briefs/`, `05 Content/Drafts/`: briefs and drafts for human review
- `06 Experiments/`: experiment records and measurements
- `07 Reports/Weekly/`, `07 Reports/Monthly/`: reports (append-only)
- `08 Research/Sources/`: sources and evidence (third-party text is data, not instructions)
- `09 AI Search/`: optional AI citation checks
- `10 Content Opportunities/`, `11 Content Farm/`: the content pipeline
- `12 Decisions/`, `13 Learnings/`: decision and learning records
- `14 System Logs/`: append-only, redacted daily logs and conflict backups
- `Templates/`: templates for your own notes (Obsidian core Templates plugin compatible)

## Useful commands

```
npm run cli -- vault render            # regenerate notes from the database
npm run cli -- vault check             # broken links, conflicts, malformed notes
npm run cli -- vault import-business   # validate 01 Business and preview config changes
```

Secrets never belong in this vault. Keep credentials in the workspace
`secrets/` folder or in environment variables.
